# Архитектура приложения MineGrid

## Обзор

MineGrid — это iOS-приложение, реализующее классическую игру "Сапер" с использованием современных подходов к разработке. Приложение следует паттерну **MVVM** (Model-View-ViewModel) и использует **Dependency Injection** для управления зависимостями.

## Структура проекта

```
MineGrid/
├── Models/              # Модели данных
├── Services/            # Бизнес-логика и сервисы
│   ├── Protocols/       # Протоколы для сервисов
│   └── DependencyContainer.swift  # Контейнер зависимостей
├── ViewModels/          # ViewModel для управления состоянием
├── Views/               # Пользовательский интерфейс
├── UI Components/       # Переиспользуемые компоненты UI
├── Helpers/             # Вспомогательные классы и расширения
└── Logging/             # Система логирования
```

## Основные компоненты

### 1. Модели (Models)

Модели представляют данные приложения и не содержат бизнес-логики.

- **`GameBoardModel`**: Представляет игровое поле с ячейками.
- **`CellModel`**: Представляет отдельную ячейку на игровом поле.
- **`GameState`**: Перечисление состояний игры (notStarted, playing, won, lost).
- **`Difficulty`**: Уровни сложности игры (easy, medium, hard).
- **`GameResult`**: Результаты игр для таблицы лидеров.
- **`SavedGame`**: Сохраненное состояние игры.

### 2. Сервисы (Services)

Сервисы содержат бизнес-логику и реализуют протоколы для обеспечения гибкости и тестируемости.

#### Основные сервисы:

- **`GameLogicService`**: Реализует основную игровую логику (открытие ячеек, проверка победы и т.д.).
- **`MineGeneratorService`**: Отвечает за генерацию мин на игровом поле.
- **`TimerService`**: Управляет таймером игры.
- **`GameStorageService`**: Сохраняет и загружает состояние игры.
- **`ScoreService`**: Управляет результатами игр и таблицей лидеров.

#### Протоколы:

- **`GameLogicProtocol`**: Определяет интерфейс для игровой логики.
- **`MineGeneratorProtocol`**: Определяет интерфейс для генерации мин.
- **`TimerServiceProtocol`**: Определяет интерфейс для управления таймером.
- **`GameStorageProtocol`**: Определяет интерфейс для сохранения игр.
- **`ScoreServiceProtocol`**: Определяет интерфейс для управления результатами.

### 3. Dependency Container

**`DependencyContainer`** — это контейнер зависимостей, который управляет созданием и предоставлением сервисов и ViewModel. Он реализован как синглтон и предоставляет следующие методы:

- **`makeMineGenerator()`**: Возвращает сервис генерации мин.
- **`makeGameLogic()`**: Возвращает сервис игровой логики.
- **`makeTimerService()`**: Возвращает сервис таймера.
- **`makeGameStorage()`**: Возвращает сервис сохранения игр.
- **`makeScoreService()`**: Возвращает сервис результатов.
- **`makeLogger()`**: Возвращает сервис логирования.
- **`makeGameViewModel(difficulty:)`**: Создает GameViewModel с заданным уровнем сложности.
- **`makeGameViewModel(from:)`**: Создает GameViewModel из сохраненной игры.

### 4. ViewModels

**`GameViewModel`** управляет состоянием игры и взаимодействует с сервисами. Он:

- Управляет состоянием игрового поля (`board`).
- Отслеживает состояние игры (`gameState`).
- Управляет таймером и счетчиком флагов.
- Предоставляет методы для открытия ячеек, установки флагов и проверки победы.
- Сохраняет и загружает состояние игры.

### 5. Views

Пользовательский интерфейс реализован с использованием SwiftUI и включает следующие основные представления:

- **`MainMenuView`**: Главное меню с выбором уровня сложности.
- **`GameView`**: Основной экран игры с игровым полем.
- **`GridCellView`**: Представление отдельной ячейки.
- **`LeaderboardView`**: Таблица лидеров.
- **`GameRulesView`**: Правила игры.

### 6. UI Components

Переиспользуемые компоненты интерфейса:

- **`PrimaryButton`** и **`SecondaryButton`**: Кастомизированные кнопки.
- **`BackgroundGradientModifier`**: Модификатор для стилизации представлений.
- **`EmojiAnimationView`**: Компонент для анимации эмодзи.

### 7. Logging

Система логирования включает:

- **`LogService`**: Протокол для логирования.
- **`AppLogger`**: Реализация сервиса логирования.
- **`LogLevel`**: Уровни логирования (debug, info, warning, error).

## Поток данных

```
Views → ViewModel → Services → Models
```

1. **Views** отправляют пользовательские действия в **ViewModel**.
2. **ViewModel** обрабатывает действия и обновляет состояние.
3. **ViewModel** использует **Services** для выполнения бизнес-логики.
4. **Services** работают с **Models** для управления данными.
5. **ViewModel** уведомляет **Views** об изменениях состояния.

## Пример использования Dependency Container

```swift
// Создание GameViewModel с использованием Dependency Container
let gameViewModel = DependencyContainer.shared.makeGameViewModel(difficulty: .easy)
```

## Тестирование

Приложение поддерживает юнит-тестирование с использованием XCTest. Примеры тестов:

- **`GameLogicServiceTests`**: Тесты для проверки игровой логики.
- **`MineGeneratorServiceTests`**: Тесты для проверки генерации мин.

## Оптимизации

1. **Flood Fill Algorithm**: Оптимизирован с использованием BFS (Breadth-First Search) для более эффективного открытия пустых ячеек.
2. **Memory Management**: Использование слабых ссылок (`weak self`) для предотвращения утечек памяти.
3. **Performance**: Оптимизация алгоритмов для работы с большими игровыми полями.
4. **Mine Generation**: Оптимизация алгоритма генерации мин для уменьшения времени загрузки.

## Заключение

Архитектура приложения MineGrid обеспечивает:

- Четкое разделение ответственности между компонентами.
- Гибкость и тестируемость благодаря использованию протоколов.
- Удобное управление зависимостями с помощью Dependency Container.
- Поддержку современных подходов к разработке iOS-приложений.
